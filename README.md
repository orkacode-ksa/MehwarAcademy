# مِحوَر

منصة SaaS متعددة المستأجرين لإدارة المقررات الأكاديمية وتوليد المحتوى بالذكاء الاصطناعي.

**ابدأ من [`docs/MASTER.md`](./docs/MASTER.md)** — الملف المرجعي الشامل: المشروع كاملًا
(الفكرة · القرارات · المعمار · نموذج البيانات · دورة العمل · الحالة والخطوة التالية) في ملف واحد.

وراجع [`PROJECT.md`](./PROJECT.md) للقرارات المقفلة ونطاق التنفيذ الفعلي،
و[`docs/lessons.md`](./docs/lessons.md) **قبل بناء أي شاشة**.

## البنية

```
client/            React + Vite + TS + Tailwind (PWA)
server/            Node + Express + TS + Prisma + PostgreSQL
packages/shared/   أنواع ومخططات zod مشتركة
```

## التشغيل محليًا

### المتطلبات
- Node.js ≥ 20
- PostgreSQL 16
- (اختياري) Redis

### الخطوات
```bash
npm install
cp .env.example server/.env   # املأ القيم — DATABASE_URL محليًا + أسرار عشوائية (openssl rand -hex 64/32)
npm run prisma:migrate --workspace=server   # يطبّق كل الهجرات، بما فيها trigger سجل التدقيق
npm run prisma:seed --workspace=server      # بيانات عرض تجريبي (اختياري)
npm run dev:server    # http://localhost:4000
npm run dev:client    # http://localhost:5173
```

### الاختبارات
```bash
npm run test --workspace=server   # يشمل tenant-isolation.spec.ts
```

### البناء والفحص
```bash
npm run build
npm run typecheck
npm run lint
```

## النشر

- **الخادم:** حاوية Docker مبنية من `server/Dockerfile` (سياق البناء = جذر المستودع، تعتمد على صورة Playwright الرسمية لتوفير Chromium لمحرك PDF). المتغيرات البيئية المطلوبة موثّقة في `.env.example`. عند الإقلاع يجب تشغيل `prisma migrate deploy` (مُدرَج كخطوة إصدار/بدء تشغيل).
- **الواجهة:** حزمة ثابتة من `vite build` (`client/dist`) تُخدَّم عبر حاوية ثابتة بسيطة (`serve`) أو CDN.

## مصفوفة التدهور الرشيق

| الخدمة الخارجية | عند التعطّل |
|---|---|
| Redis | الكاش وحدود المعدل تتحول لوضع الذاكرة المحلية (نسخة واحدة فقط) — النظام يعمل بأداء أقل، لا انقطاع |
| التخزين الكائني (وضع وهمي حاليًا) | الرفع/التنزيل يعملان عبر قرص محلي مؤقت خلف endpoint محمي — غير دائم بين عمليات النشر |
| Gemini (نص/TTS) | يعمل بوضع وهمي حتمي: نص/صوت صامت تجريبي بدل محتوى حقيقي، بلا انقطاع للميزة |
| بوابة الدفع | checkout ينشئ فاتورة ودفعًا وهميين بوضوح — لا تحصيل حقيقي، والاشتراك يُفعَّل عبر webhook محاكى لا عبر إعادة توجيه المتصفح |
| مزوّد الفوترة الإلكترونية | فاتورة نصية مبسّطة موسومة "غير نظامية" بدل ZATCA حقيقية |
| مزوّد البريد | الرسائل تُسجَّل في اللوق بدل الإرسال الفعلي |
| Cloudflare (غير مربوط بعد) | فحص `X-Origin-Auth` معطّل تلقائيًا حتى يُضبط `CF_ORIGIN_SECRET` — موثّق كفجوة أمنية مؤقتة |

## خطة الاستجابة للحوادث (ملخّص تشغيلي)

1. **اكتشاف:** تنبيه Sentry (غير مفعّل بعد — يحتاج `SENTRY_DSN`) أو شكوى → افحص اللوق بـ `requestId`.
2. **احتواء:** عطّل endpoint المستهدف أو أوقف ميزة الذكاء عبر متغيرات البيئة (`GEMINI_API_KEY` فارغ = وضع وهمي فوري).
3. **اشتباه اختراق:** بدّل كل الأسرار في `server/.env`، ثم ارفع `tokenVersion` لكل المستخدمين (سكربت مستقبلي)، وخذ نسخة من اللوق والقاعدة قبل أي تغيير.
4. **استئصال وتعافٍ:** أصلح السبب الجذري، انشر، وراقب 48 ساعة.
5. **إبلاغ نظامي:** أي تسريب بيانات شخصية يستوجب تنسيقًا قانونيًا وفق PDPL السعودي.

`rollback`: إعادة نشر آخر إصدار ناجح من لوحة Railway مباشرة (بلا خطوة يدوية إضافية).
