## ٤ — المستأجر الأول

أستاذ جامعي واحد · قسم الأحياء · **مجاناً مدى الحياة** · شريك تصميم لا عميل.
المقابل غير المالي المطلوب صراحةً: مواد مقرر حقيقية · ملاحظات أسبوعية · إذن بالاستخدام كحالة مرجعية · **موافقة مكتوبة على معالجة البيانات** (وجود طلاب حقيقيين لا يعفينا منها).
الفاتورة المتوقّعة: **≈ ٣ دولارات شهرياً**، وتنخفض أكثر إن نجحت أتمتة NotebookLM على حسابه.

## ٦ — ⚠️ شرط تشغيلي لا يُنسى: دور قاعدة البيانات

**عزل المستأجرين يسقط بالكامل إن اتصل التطبيق بمستخدم قاعدة بيانات خارق (superuser).**

اكتُشف هذا بالقياس أثناء بناء المرحلة ٧ لا بالافتراض: بالسياسات مفعّلة تمامًا كان كل
مستأجر يرى صفوف الآخر، لأن المستخدم الخارق يتجاوز RLS تجاوزًا صامتًا — بلا خطأ ولا تحذير.
و`FORCE ROW LEVEL SECURITY` لا يمنعه؛ إنما يُلزم مالك الجدول وحده.

**المطلوب لكل بيئة (مرة واحدة):**
```sql
ALTER ROLE mihwar_app LOGIN PASSWORD '<من مدير الأسرار>';
```
ثم يُوجَّه `DATABASE_URL` إلى `mihwar_app` (الهجرات تبقى بالدور المالك).

الدور نفسه ومنحه تُنشئهما هجرة `20260906000001_row_level_security`. وشبكة الأمان:
`src/lib/rlsGuard.ts` يفحص عند الإقلاع أن الدور المتصل غير خارق ولا يحمل `BYPASSRLS`،
**ويمنع إقلاع الخادم في الإنتاج** إن كان كذلك. خادم لا يعمل أهون من خادم بلا عزل.

| الجدار الأول: امتداد Prisma يحقن الشرط ويفشل مغلقًا | ✅ |
| الجدار الثاني: سياسات RLS على ٢٠ جدولًا + `FORCE` | ✅ |
| حارس الإقلاع ضدّ الدور الخارق | ✅ |
| هجرة بتعبئة مُختبَرة على قاعدة بها بيانات | ✅ |
| مصفوفة العزل: جدول جديد بلا قرار عزل يكسر البناء | ✅ ١٠ اختبارات |

بلا سياق. كلها أُصلحت، وكلها كانت ستُنتج «يعمل لكن بلا عزل».
