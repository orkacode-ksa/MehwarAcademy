# اختبار الحمل — ذروة بداية الفصل

الأداة: `server/scripts/loadtest/peak.mjs` (autocannon). تشغيلها:

```sh
cd server && npm run build && NODE_ENV=production PORT=4500 node dist/index.js   # نافذة
node scripts/loadtest/peak.mjs http://127.0.0.1:4500 150 30 100                    # أخرى
```

السيناريو: ١٥٠ أستاذًا (كلٌّ بعنوان IP مختلف) ← موجة دخول في اللحظة نفسها ← ٣٠ ثانية تصفّح
مختلط بمئة اتصال متزامن بأوزان الاستخدام الفعلي (الرئيسية · عدّاد الإشعارات · شريط النظام ·
حسابي · مقرراتي). التوليد خارجه عمدًا: يُقاس بطول طابور العامل لا بزمن الاستجابة.

## النتائج (٢٩ سبتمبر ٢٠٢٦ — عملية Node واحدة وPostgres على الجهاز نفسه، ٤ أنوية)

| المقياس | قبل | بعد |
|---|---|---|
| موجة ١٥٠ دخولًا متزامنًا — p50 | 4,689ms | 1,171ms |
| موجة ١٥٠ دخولًا متزامنًا — p95 | 8,511ms | 1,708ms |
| ذاكرة التجزئة في الذروة (تقدير) | ~٩.٦ GB | ~٢.٩ GB |
| التصفّح: طلبات/ثانية | 360 | 360 |
| التصفّح: p50 / p90 / p99 | 254 / 463 / 542ms | 252 / 460 / 544ms |
| أخطاء · ردود غير 2xx | 0 · 0 من 10,801 | 0 · 0 من 10,788 |

زمن كل مسار منفردًا: الرئيسية 14ms · مقرراتي 8ms · حسابي 5ms · عدّاد الإشعارات 4ms · الشريط 1.5ms.

## ما تغيّر بعد القياس

- **تجزئة كلمات المرور** (عنق الزجاجة الوحيد): argon2id بإعدادات OWASP (19MiB · t=2 · p=1)
  بدل افتراضي المكتبة (64MiB · t=3 · p=4)، و`UV_THREADPOOL_SIZE=16` في الحاوية. الهاشات القديمة
  تُرقّى صامتة عند أول دخول ناجح.
- **التوليد في عامل مستقل** (`mihwar-worker`): لا يزاحم طلبات الويب، ولا تضيع مهمة بإعادة النشر.

## القراءة

عملية واحدة تخدم ~٣٦٠ طلبًا/ثانية (≈ ٢١ ألف طلب/دقيقة) بلا خطأ. التصفّح محدود بخيط Node الواحد،
فالتوسّع أفقي: **نسخة ثانية من خادم الويب** في Railway (Replicas = 2) تضاعف السعة — الجلسات
بتوكنات بلا حالة، وحدود المعدّل في Redis المشترك، فلا يلزم تعديل كود. يُنصح بها قبل أول فصل
يتجاوز ألف أستاذ نشط.
